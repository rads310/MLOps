5. Ответы на контрольные вопросы
Что фиксирует uv.lock и почему его недостаточно?
uv.lock фиксирует точные версии Python-пакетов и их зависимостей. Для ML-проекта этого недостаточно, так как результат зависит от данных, кода и параметров, которые версионируются отдельно через Git и DVC.
Что хранится в Git, а что в DVC?
В Git хранятся код, конфиги (params.yaml, dvc.yaml) и легкие .dvc-метафайлы (содержащие md5-хеши). В DVC-хранилище (DagsHub) хранятся сами тяжелоловесные файлы данных и моделей.
Как DVC определяет, какие этапы пересчитывать?
DVC сравнивает md5-хеши зависимостей (deps), параметров (params) и выходов (outs), указанных в dvc.yaml для каждого этапа. Если хеши не изменились, этап пропускается.
Почему ключи задаются с --local?
Флаг --local записывает секреты в .dvc/config.local, который внесён в .gitignore. Это предотвращает утечку паролей и токенов в публичный репозиторий.
Почему dvc push делается раньше git push?
Чтобы при отправке коммита в Git соответствующий ему массив данных уже гарантованно находился в удалённом хранилище DVC.
Какие две команды возвращают проект к состоянию прошлой версии?
git checkout <tag/commit> (возвращает код и метафайлы) и dvc checkout (восстанавливает соответствующие файлы данных из кэша).
Почему случайное разбиение данных с датой завышает оценку качества?
Данные содержат временную структуру. Случайное разбиение приводит к утечке данных из будущего в обучающую выборку (Data Leakage), завышая R² на тесте.

Ответы на контрольные вопросы к ЛР2
1. Чем запуск (run) отличается от версии модели в реестре?
Запуск (Run): Запись одиночного эксперимента в MLflow Tracking, содержащая гипотезу, параметры, метрики и логи обученной модели. Запусков может быть сотни.
Версия модели в Реестре (Model Registry): Одобренный, именованный и отбранный артефакт модели, имеющий жизненный цикл (версии, алиасы champion/challenger). В реестр попадают только лучшие модели из успешных запусков.
2. Зачем разделять champion и challenger, если можно просто взять последнюю версию?
Последняя обученная версия модели не всегда лучше предыдущей (она может переобучиться или быть обучена на неудачных гиперпараметрах).

champion — текущая проверенная рабочая модель, используемая в продакшене.
challenger — новая модель-кандидат, проходившая проверку. Она становится champion только если показывает метрики строго выше текущего чемпиона.
3. Что произойдёт, если train и evaluate откроют разные запуски?
В интерфейсе MLflow образуется рассогласование: создадутся два разрозненных запуска. В первом (от train) будут параметры и сама модель, но не будет итоговых метрик теста. Во втором (от evaluate) будут только метрики без параметров обучения. Сравнение моделей станет невозможным.

4. Почему DVC может не выполнить обучение при изменении params.yaml и как это обойти?
DVC может не выполнить этап, если:

Изменённый параметр в params.yaml не был явно указан в секции params: данного этапа в dvc.yaml.
Результаты этапа уже есть в кэше.
Как обойти: Использовать флаг принудительного перезапуска: dvc repro -f (force).
5. Что даёт сигнатура модели и почему её стоит записывать вместе с моделью?
Сигнатура (infer_signature) фиксирует схему входных и выходных данных (названия колонок и их типы данных).
Она позволяет:

Проверять типы входных данных при вызове предсказания (инференса);
Автоматически отклонять некорректные запросы до передачи их в модель;
Документировать интерфейс модели.
6. Почему окружение модели фиксируется списком версий, а не определяется автоматически?
Автоматическое определение пакетов MLflow часто ошибается или тянет конфликтующие локальные зависимости системной среды (например, различия между Colab и локальным Python). Явное указание версий (pip_requirements) гарантирует, что модель запустится в любой среде без ошибок десериализации.

7. Как забрать модель из реестра, не зная ни пути к файлу, ни номера версии?
Используя URI с алиасом модели в MLflow:

Python

import mlflow
model = mlflow.sklearn.load_model("models:/<имя_модели>@champion")
Служба сама найдет и загрузит актуальную модель с меткой champion.
